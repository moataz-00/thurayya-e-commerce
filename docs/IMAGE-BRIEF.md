# Photography

Every image on the site is filled with real photography, sourced from Unsplash and mapped
in one registry. This document covers how that works, what each slot is for, and how to
replace the stock with the commissioned Thurayyā shoot.

> **Read this first.** The current images are Unsplash stock. They are free to use under
> the [Unsplash licence](https://unsplash.com/license), including commercially and without
> attribution — but **none of them is an actual Thurayyā product**. They stand in for the
> shoot. Do not launch a commercial storefront showing stock photographs as the pieces
> being sold. See "Replacing the stock" below.

---

## How it works

One registry, `src/lib/images.ts`, maps every slot to an image id. One component,
`ShotSlot`, renders it.

```tsx
<ShotSlot
  label={{ en: "chandelier, front elevation", ar: "ثريا، واجهة أمامية" }}
  src="photo-1787682446632-2a1e8569da1a"
  sizes="(max-width: 640px) 50vw, 25vw"
  priority
/>
```

| Prop        | What it does                                                                    |
| ----------- | -------------------------------------------------------------------------------- |
| `src`       | An image id — an Unsplash photo path, a local path (`/images/…`), or any URL     |
| `label`     | The alt text, and the fallback brief if the image is missing or fails            |
| `sizes`     | The responsive hint. Every call site sets one; get it wrong and the browser over-downloads |
| `priority`  | `loading="eager"` + `fetchpriority=high`. Set on above-the-fold heroes only      |
| `tone`      | 1–4 placeholder ground, used only when there is no image                         |
| `dark`      | Placeholder variant for onyx and emerald surfaces                                |
| `position`  | `object-position`, when a crop needs nudging                                     |

`resolveImage(id)` in `src/lib/images.ts` turns an id into a `src` plus a `srcSet`.
Unsplash resizes on its own CDN, so the browser picks from
`400 / 640 / 900 / 1280 / 1600` widths and nothing is optimised server-side — dev and
production behave identically, and there is no `sharp` dependency or `remotePatterns`
config to keep in sync.

**If an image 404s or the network is down, `ShotSlot` falls back to the labelled
placeholder.** The photography brief is never lost; it is one `onError` away.

## What the registry holds

| Export             | Covers                                                                |
| ------------------ | ---------------------------------------------------------------------- |
| `PRODUCT_IMAGES`   | All 31 products — `hero`, `lifestyle`, and optional `detail` / `lit` / `scale` |
| `FAMILY_FALLBACK`  | The detail / lit / scale frames a product does not set, per family     |
| `CATEGORY_IMAGES`  | 14 categories — `tile` and `banner`                                    |
| `ROOM_IMAGES`      | 8 rooms — `hero` and `tile`                                            |
| `COLLECTION_IMAGES`| 6 collections — `hero` and three campaign frames                       |
| `JOURNAL_IMAGES`   | 6 articles — `hero` and the in-article `shot` blocks, in body order    |
| `CRAFT_IMAGES`     | The five material macros                                               |
| `TEAM_IMAGES`      | Four portraits, in `TEAM` order                                        |
| `SHOWROOM_IMAGES`  | Zamalek, Dubai, Riyadh                                                 |
| `SITE_IMAGES`      | Every one-off — home hero, story, collection band, consultation, listing banners, custom hero and five projects, trade, about, sign-in, and the four mega-menu frames |

Data files attach these when they build their exports, so a page reads `category.tileSrc`
or `product.shots[0].src` and never touches the registry itself. The one exception is
genuinely one-off slots on a page, which import `SITE_IMAGES` directly.

## The slots, and what each is for

### Per product — six frames

Generated by `shotsFor()` in `src/lib/mock/products.ts`, so every product has all six.

| Slot        | Purpose                                                     | Ratio | Notes                                             |
| ----------- | ------------------------------------------------------------ | ----- | -------------------------------------------------- |
| `hero`      | Front elevation on ivory. The catalogue shot.                | 4:5   | Also the card image at rest                       |
| `detail`    | Macro — brass arm and cup junction (furniture: joint/edge)   | 1:1   | Close enough to read patina and file marks        |
| `lit`       | At night, 2700K (furniture: raking light across the top)     | 1:1   | The reason someone buys it                        |
| `video`     | 12s rotation, muted loop                                     | 4:5   | Currently shows the hero frame                    |
| `lifestyle` | The room the piece belongs in                                | 4:5   | Also the card image on hover                      |
| `scale`     | Dimension overlay drawing                                    | 4:5   | A line drawing over the hero, not a photograph    |

**`hero` and `lifestyle` must be shot to frame together** — the card cross-fades between
them over 700ms, which is the most visible piece of photography direction on the site.

### Elsewhere

- **Categories** — a 3:4 tile and a wide banner. Banners sit behind onyx at 40% with a
  scrim, so they need strong shape and very little detail.
- **Collections** — a full-bleed hero plus three campaign frames: a wide room shot, a
  material macro, and one behind-the-scenes frame from the atelier. The last is not
  optional; it is what separates a collection page from a catalogue.
- **Rooms** — a wide hero shot at the hour named in the room copy, plus a 16:11 tile.
  **The heroes carry hotspots** at `{ x, y }` percentages declared in `src/lib/mock/rooms.ts`.
  Change the composition and those percentages have to move with it.
- **Journal** — a 16:10 hero per article, plus the `shot` blocks named in the body. The
  diagram briefs ("three light layers annotated", "table width to fixture diameter") are
  illustrations, not photographs.
- **Studio** — home hero and story, the five custom-project frames, trade samples and two
  project squares, the about hero and atelier wide, four team portraits, three showrooms.

## Art direction

- **Warm, never white.** Backgrounds are Moon Ivory `#F2EEE5`, not paper white.
- **2700K.** Every lit shot at the colour temperature the fixtures ship with.
- **Space.** Photography gets the room a showroom would give an object. The object does not
  fill the frame.
- **No people in product shots.** Lifestyle frames may show a room in use; the catalogue
  hero is the object alone.
- **Never mirrored.** Photography is never flipped for RTL.

### Dark heroes

Heroes on onyx run at **40–45% opacity with a gradient scrim** over them, which is what
keeps ivory text at an accessible contrast. The design specified 16–20% for the *placeholder*
pattern; real photography needs the higher value to read at all. If you swap a hero for a
much brighter photograph, check the text contrast again rather than assuming.

## Replacing the stock with the real shoot

Four steps for the whole site, because every image goes through one registry and one
component.

1. Put the files under `public/images/` (or a CDN).
2. Change the ids in `src/lib/images.ts` from `photo-…` to `/images/…`. `resolveImage`
   already handles both — a non-Unsplash id is passed straight through as `src`.
3. **Rewrite every `label` as a real alt description.** Right now the labels are production
   briefs — "hero — chandelier front elevation on ivory, 1600×2000" is a note to a
   photographer, not something a screen reader should read out. This is the step that is
   easiest to skip and matters most. See [ACCESSIBILITY.md](ACCESSIBILITY.md).
4. If you self-host, add your own `srcSet` widths to `resolveImage` — the Unsplash branch
   builds them from query parameters, which local files will not have.

Until step 3 is done, the site is announcing photography briefs to screen-reader users.
Treat it as a launch blocker.
